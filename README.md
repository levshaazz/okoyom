# Окоём · Ходоки

Сайт кампании «Ходоки». Этот срез — статическая оболочка на GitHub Pages: лист героя, сумка и очередь «ждут мастера». Сервера ещё нет.

Адрес после включения Pages: <https://levshaazz.github.io/okoyom/>

## Что уже работает

- Гостевая главная, доска Конторы и публичная летопись.
- Лист трёх пробных героев: Римте Норейка, Тойво Салми, Ждан Корш. Уровень, опыт, три полосы, навыки с отметками, Дар (только свой и мастеру), журнал, деньги.
- Сумка со слотами груза (дроби), фильтрами, карточкой вещи. Надеть и снять, выпить зелье — сразу. Выброс и передача — в очередь.
- Две руки: одноручное, щит слева, заклинание, факел, посох, боевой свиток; лук и двуручное занимают обе. До четырёх наборов «Избранное». Смена рук сразу и пишется в журнал.
- Свитки знания: в сумке туманное описание, «Прочесть и выучить» открывает название. Мастер выдаёт их с пульта «Выдать».
- Дозор мастера: карточки всех героев, лента и красные флаги. Обновление — подписка на локальный стор.
- Игрок ставит отметку навыка или просит перк: заявка висит пунктиром «ждёт мастера». Мастер на пульте принимает или отклоняет. Отклонение не меняет лист.
- Правки живут в IndexedDB этого браузера (если хранилище недоступно — в `localStorage`). Обновление страницы их не стирает. Кнопка в пробном входе возвращает семя.
- Карта (`/karta`): трёхмерный учебный берег (three.js только на этой странице). Рельеф, вода, свет и облачный туман войны. Камера: сдвиг, зум, наклон и поворот. Подписи мест, слои и карточка как у карты мира. Мастер кликает по рельефу: метка или туман всем/герою. Если WebGL нет — плоский вид той же текстуры. Настоящую картинку и карту высот подставляют в `src/data/map-manifest.ts`.

## Чего ещё нет

Настоящего входа, Supabase, RLS, записок, текста книг, вики-статей, нарезанных тайлов карты, ремесла, живой сессии за столом. Передача всегда «через мастера», потому что стола в сети нет. Кузня — заглушка. Туман карты в этом срезе рисует интерфейс: закрытая клетка не попадает в картинку тестового берега, но это не серверная отсечка.

Пробный вход в шапке (**Войти героем** или имя героя) только переключает роль в браузере. Это не защита: кто угодно может открыть пульт. Тестовые Дары лежат в коде страницы; чужой Дар прячет интерфейс, не сервер. Тайн кампании в репозитории нет — только выдуманные герои.

Полные правила и спецификация в этот репозиторий не входят.

## Как включить GitHub Pages

Workflow `.github/workflows/pages.yml` собирает сайт и выкладывает его через GitHub Actions. Один раз в репозитории:

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Влить ветку в `main` (или запустить workflow вручную: Actions → Pages → Run workflow).

Команда `gh` из этой среды не меняет настройки репозитория, поэтому источник Pages нужно включить руками, если он ещё не Actions.

Локально:

```bash
npm install
npm test
npm run dev
```

Сайт открывается на `http://127.0.0.1:4321/okoyom/`. Сборка: `npm run build`, просмотр сборки: `npm run preview`.

## Куда ляжет Supabase

Страницы ходят только в `DataStore` (`src/lib/store.ts`). Сейчас это `CampaignStore` поверх семени и IndexedDB. Позже тот же интерфейс может вызывать RPC (`request_change`, `gm_decide`, `transfer_item`, …) — экраны переписывать не нужно. Схема рядов повторяет таблицы спецификации: `heroes`, `skills`, `perks`, `items`, `item_instances`, `change_requests`, `transfers`, журнал аудита.
